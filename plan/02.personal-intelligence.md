# PrivatePrompter - Personal Intelligence (Local RAG)

## Executive Summary
This document details the expansion of PrivatePrompter to include a "Personal Intelligence" layer. By integrating LanceDB, the application will index the user's past successful prompts and local documents (.md, .txt, .pdf) to inject highly personalized context into the meta-prompt pipeline—all executed 100% locally.

## Tech Stack Addition
*   **Vector Database:** LanceDB (Rust implementation)
*   **Embedding Model:** `nomic-embed-text` or `all-MiniLM-L6-v2` (GGUF via `llama.cpp` sidecar)
*   **File Parsers (Rust):** `pdf-extract` (PDF), `pulldown-cmark` (Markdown), standard text readers.

---

## Execution Phases

### Phase 1: Vector Database Setup
1.  **LanceDB Integration:** Add the `lancedb` crate to the Rust backend.
2.  **Storage Configuration:** Initialize a local LanceDB storage directory inside the macOS app data folder (`~/Library/Application Support/com.privateprompter.app/lancedb/`).
3.  **Schema Definition:** Create two primary tables:
    *   `prompt_history`: [id, original_text, optimized_prompt, timestamp, vector_embedding]
    *   `knowledge_base`: [id, file_name, chunk_text, vector_embedding]

### Phase 2: Local Embedding Engine
1.  **Embedding Sidecar Config:** Configure the existing `llama.cpp` sidecar to support embedding generation, or spawn a secondary sidecar specifically for a lightweight embedding model (e.g., `nomic-embed-text.gguf`).
2.  **Rust Embedding Pipeline:** Create a Rust function that takes any string, sends it to the embedding sidecar, and returns a high-dimensional vector array.

### Phase 3: File Ingestion & Parsing
1.  **Context UI (React):** Create a "Knowledge Base" tab in the React settings window featuring a drag-and-drop zone for files.
2.  **File Readers (Rust):** 
    *   Implement basic `.txt` and `.md` ingestion.
    *   Integrate a crate like `pdf-extract` to extract raw text from `.pdf` files.
3.  **Chunking Logic:** Write a text chunker (e.g., splitting by paragraphs or fixed token lengths with overlap) to prepare the extracted text for embedding.
4.  **Indexing:** Run the chunks through the embedding pipeline and insert them into the `knowledge_base` LanceDB table.

### Phase 4: Dynamic RAG Pipeline (The Retrieval)
1.  **Query Embedding:** When the user triggers the global hotkey on their raw text, first embed their raw text into a query vector.
2.  **Vector Search:** Execute a similarity search in LanceDB against the `knowledge_base` and `prompt_history` tables to retrieve the top 3 most relevant chunks and past prompts.
3.  **Meta-Prompt Injection:** Dynamically build the system prompt sent to the LLM:
    ```text
    You are an expert prompt engineer. Rewrite the user's raw input into a structured prompt.
    
    Use the following user context to inform the constraints and domain knowledge:
    [INJECTED KNOWLEDGE BASE CHUNKS]
    
    Here are examples of the user's preferred prompt style:
    [INJECTED PAST PROMPTS]
    
    Raw Input: [USER HIGHLIGHTED TEXT]
    ```

### Phase 5: Feedback Loop
1.  **Auto-Saving Prompts:** Add a toggle in the settings: "Remember successful prompts."
2.  **Background Indexing:** If enabled, every time the user generates a new prompt via the hotkey, asynchronously embed the final result and save it to the `prompt_history` LanceDB table to continuously improve few-shot examples.
