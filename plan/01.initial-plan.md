# PrivatePrompter - MVP Architecture Plan

## Executive Summary
This document outlines the architecture and execution plan for building **PrivatePrompter**, a privacy-first, standalone macOS desktop application. The tool allows users to highlight text anywhere on their system, press a global hotkey, and have an embedded local LLM instantly rewrite it into an optimized prompt using meta-prompting.

## Tech Stack
*   **Framework:** Tauri v2 (React + TypeScript Frontend, Rust Backend)
*   **OS Target:** macOS (Apple Silicon & Intel)
*   **Inference Engine:** Embedded `llama.cpp` (run as a Tauri Sidecar)
*   **LLM Source:** Downloaded dynamically from HuggingFace (GGUF format)

---

## Execution Phases

### Phase 1: Project Initialization & Permissions
1.  **Initialize Tauri v2:** Scaffold a new Tauri project using React, TypeScript, and Vite.
2.  **macOS Permissions:** Configure `tauri.conf.json` and `Info.plist` to request necessary macOS Accessibility and Screen Recording permissions (required for global hotkeys and clipboard/text manipulation).
3.  **UI Setup:** Create a minimal system tray app (menu bar) and a primary settings window using Tailwind CSS.

### Phase 2: Dynamic Model Management
1.  **Hardware Detection (Rust):** Write a Rust command to detect macOS system memory to recommend the right model size (e.g., Llama 3.2 1B vs 3B).
2.  **HuggingFace Downloader (Rust):** Implement a background downloader using `reqwest` that fetches `.gguf` files from HuggingFace. 
3.  **Download Manager UI (React):** Build a settings view showing download progress, model selection, and disk space usage.

### Phase 3: The Inference Engine (llama.cpp Sidecar)
1.  **Binary Bundling:** Pre-compile `llama.cpp` for macOS (arm64 and x86_64) and configure it as a **Tauri Sidecar**. This isolates the inference engine from the main app thread.
2.  **Sidecar Manager (Rust):** Write Rust logic to spawn the `llama.cpp` sidecar process on app boot, pointing it to the downloaded `.gguf` model file and exposing its local HTTP API (`127.0.0.1:11434` or similar).
3.  **Lifecycle Hook:** Ensure the sidecar process is gracefully terminated when the user quits the Tauri app.

### Phase 4: OS Integration (Hotkeys & Clipboard)
1.  **Global Hotkey (Rust):** Integrate `tauri-plugin-global-shortcut` to listen for a user-configured hotkey (e.g., `Cmd+Shift+Space`).
2.  **Clipboard Interception (Rust):** Upon hotkey press, use the `enigo` crate (or `arboard`) to:
    *   Simulate `Cmd+C` to copy the currently highlighted text to the clipboard.
    *   Read the clipboard contents into memory.
3.  **Text Replacement (Rust):** After LLM processing, write the new text back to the clipboard and simulate `Cmd+V` to paste it over the original text.

### Phase 5: The 4-Tier Context Detection Pipeline
To ensure PrivatePrompter acts intelligently on whatever you are currently working on, the Rust backend executes a sub-150ms state detection pipeline before generating a prompt:

| Tier | Execution Layer | Latency | Mechanism / Action |
| :--- | :--- | :--- | :--- |
| **Tier 1: OS OS-Level Inspection** | Rust + AppleScript/JXA | 0-10ms | Instantly fetches the frontmost application name. If a browser is active, extracts the active tab's URL and title. |
| **Tier 2: Content Heuristics** | Regex / Keyword Engine | 10-30ms | Evaluates the Tier 1 data (e.g., `github.com` = coding context, `figma.com` = design context) to route to specific tool profiles. |
| **Tier 3: Local 1B Classifier** | Embedded `llama.cpp` | 30-150ms | If heuristics are ambiguous, a tiny local model classifies the intent based on highlighted text and window context. |
| **Tier 4: Universal Fallback** | `prompt-master` Rule | Instant | If OS privacy settings block detection, defaults silently to the Universal Fingerprint template. |

### Phase 6: The Meta-Prompt Workflow
1.  **The Prompt Wrapper:** Create a configuration file containing the strict meta-prompt (e.g., *"You are an expert prompt engineer. Transform the following raw thought into a structured prompt using XML tags. Output ONLY the prompt. Raw thought: [INPUT]"*). Use `nidhinjs/prompt-master` skill as a [reference](https://raw.githubusercontent.com/nidhinjs/prompt-master/refs/heads/main/SKILL.md) 
2.  **The Execution Loop:** 
    *   Hotkey triggered -> Text copied.
    *   Show a loader to the user.
    *   Rust passes text + meta-prompt to the local `llama.cpp` sidecar API.
    *   Rust waits for the response (or streams it).
    *   Rust pastes the result back to the active window.
3.  **Error Handling:** Implement UI toast notifications (via Tauri's notification plugin) to alert the user if no text is selected or if the model is still loading.
